# ตัวประเมินความถูกต้อง (ย้าย 28 ตุลาคม 2026)

ดับเบิลคลิก `run_evaluation.cmd` ที่รากโปรเจกต์ เลือก 1, 2 หรือ 3
ผลรอบใหม่อยู่ใน `evaluation/runs/<วันเวลา>/results.json` ไม่ทับผลทดลองเดิม

| ตัวเลือก | ข้อมูลที่เข้าโมเดล |
|---|---|
| 1 | พิกัดก่อน Renderer ชุด no_hold_no_smoothing เดิม 200 คลิป |
| 2 | พิกัด RTMW ที่ตรวจจากภาพ Animation (baseline pixels ของ oracle200) |
| 3 | พิกัดลำตัว RTMW ร่วมกับมือและสถานะมือจาก Renderer — ไม่ใช่ image-only |

ตัวเลือก 2 ไม่ใช่การเลือกวิธี Experiment 2 ที่คะแนนสูงสุดจากทุกการทดลอง
โค้ดวิธีอื่นและผลเดิมยังเก็บใน `evaluation/model-results` และ `recognition_audit`

ตัวเปิดนี้ **รันโมเดลใหม่จากข้อมูลนำเข้าที่เก็บไว้** ไม่ได้สร้างภาพและตรวจจับจุดใหม่
Experiment 2–3 ใช้อาร์เรย์ที่ผ่าน normalization เดิมแล้ว จึงไม่ normalize ซ้ำ
ใช้ 27 จุดเดิมและทาย 2,000 คลาส ไม่จำกัดคำตอบเฉพาะคำที่ทดสอบ
คะแนนเป็นความสามารถรู้จำคำ ไม่ใช่เปอร์เซ็นต์ความเหมือนหรือการรับรองความถูกต้องของ ASL

## คำสั่ง

```powershell
.\run_evaluation.cmd --experiment 1 --model stgcn --limit 200
.\run_evaluation.cmd --experiment 1 --model slgcn --limit 200
.\run_evaluation.cmd --experiment 2 --limit 200
.\run_evaluation.cmd --experiment 3 --limit 200
```

เครื่องเพื่อนให้รัน `setup_friend.cmd` เพื่อสร้าง `.venv` ภายในโปรเจกต์
ตัวเปิดเลือก environment ในโปรเจกต์ก่อน โดยเครื่องเดิมยังมี fallback ไป sibling checkout
เปลี่ยนได้ด้วยตัวแปร `SIGN_EVAL_PYTHON` หรือ `SIGN_PYTHON` (ต้องมี torch, numpy, pandas, PyYAML)
ตัวตรวจภาพมี environment อยู่ใน `recognition_audit/rtmpose_env` และ `paired_video_env`
environment เหล่านี้เหมาะกับเครื่องเดิม ไม่ใช่แพ็กเกจย้ายข้ามเครื่องโดยตรง

## การจัดเก็บและข้อควรระวัง

- โค้ดถูกคัดลอกแยกจากต้นฉบับ ไม่เปลี่ยนระบบหลักหรือวิธีทดลอง
- โมเดล ภาพ วิดีโอ อาร์เรย์ และไฟล์ทดลองขนาดใหญ่ใช้ **NTFS hard link** บนไดรฟ์ C เพื่อประหยัดพื้นที่
- hard link ไม่ใช่สำเนาสำรองอิสระ: ถ้าเขียนทับเนื้อหาไฟล์ที่ลิงก์ ต้นฉบับจะเปลี่ยนด้วย ห้ามแก้ไฟล์ผลเก่าโดยตรง
- การทดลองใหม่ต้องเขียนลงโฟลเดอร์ใหม่ ตัวเปิดด้านบนทำเช่นนั้นแล้ว
- การลบชื่อไฟล์ฝั่งต้นฉบับอย่างเดียวไม่ทำให้ชื่อที่ลิงก์ฝั่งนี้หาย แต่ยังไม่แนะนำให้ลบต้นฉบับหรือ environment เดิม
- รายงาน/protocol เดิมเก็บเส้นทางและ hash เดิมไว้เป็นหลักฐาน ไม่ได้แก้ประวัติให้ดูเหมือนรันที่ใหม่
- สคริปต์วิจัยเก่าบางตัวป้องกันการรันทับหรือเช็ค hash ของ production เดิม หากตรวจไม่ผ่านให้สร้างรอบใหม่ ห้ามปิดการตรวจเพื่อให้ผ่าน
- ย้ายโค้ดตรวจภาพและข้อมูลเดิมมาด้วย แต่ไม่ได้รันทุกวิธีตรวจภาพทั้งหมดซ้ำหลังย้าย
- Git เก็บเฉพาะ source/คู่มือ/license ไม่เก็บโมเดล ฐานข้อมูล environment ภาพ/วิดีโอ หรือผลดิบ จึง clone Git อย่างเดียวแล้วยังรันประเมินไม่ได้
- cache ติดตั้งชั่วคราว `uv-cache` ไม่จำเป็นต่อการทดลองและไม่ได้รับรองการย้าย
